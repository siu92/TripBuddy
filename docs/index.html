문제와 담당 역할

여행 조건은 따로 정할 수 없었습니다

예산은 교통편과 숙소 선택에 영향을 주고, 날짜와 숙소 위치는 여행 동선을 바꿉니다. 여행지에서 계획이 달라지면 이동 경로와 경비도 다시 확인해야 합니다.

저는 이 조건들을 사용자가 선택하는 순서로 연결하고, 생성한 일정을 직접 수정할 수 있는 화면을 설계·구현했습니다.

PM · 프로젝트 진행 총괄

프로젝트 타임라인을 수립하고, 팀원별 역할과 작업 기한을 정해 진행 상황과 기한 준수를 관리했습니다. 멘토링 자료 준비와 팀 회의 진행도 맡아 일정 관리부터 기획·구현·발표까지 프로젝트 전 과정을 이끌었습니다.

직접 설계·구현한 범위

입력 흐름과 화면 구성, React 프론트엔드, 지도·일정 편집·모바일 화면, API 연동

팀과 연결한 범위

핵심 설계 판단

예산 → 출발지·목적지 → 날짜 → 교통·숙소 → 취향 → 일정 생성

01. 예산을 선택의 기준으로

‘주어진 예산 안에서 일정을 만든다’는 서비스 목적에 맞춰 첫 단계에 예산을 뒀습니다. 이후 교통편과 숙소를 고르고 일정을 생성할 때 기준으로 사용합니다.

02. 출발지와 목적지는 다른 방식으로

출발지는 자차 이동 시간을 계산할 수 있도록 시·구·동과 주소로 자세히 선택합니다. 목적지는 ‘속초나 해운대에 가고 싶다’는 생각에 맞춰 관광 지역과 명소 중심으로 구성했습니다.

03. 서로 필요한 정보부터 순서대로

교통편과 객실 상황을 고려하려면 날짜가 먼저 필요하고, 주변 동선을 정하려면 숙소 위치가 필요합니다. 이 조건을 정한 뒤 여행 테마와 음식 취향을 더하도록 배치했습니다.

입력 화면을 나열하기보다, 다음 선택에 필요한 정보를 먼저 확보하도록 설계했습니다.

설계를 바꾼 사례

출발시각을 모든 사용자에게 묻지 않기로 했습니다

처음에는 날짜 선택 화면에 출발시각을 함께 넣었습니다. 하지만 항공·KTX 여행에서는 사용자가 입력한 시간보다 예매한 티켓 시각이 일정의 기준이 됩니다.

처음 구상

날짜와 출발시각을 함께 입력

교통수단이 정해지기 전부터 모든 사용자에게 같은 시간 정보를 요청

수정한 설계

교통수단에 맞춰 시간 결정

공통 날짜 화면에서는 시간 입력을 제거하고, 자차를 선택한 경우에만 출발·도착 시각 설정

항공·KTX는 티켓 시각을 사용하고, 자차는 직접 정하는 방식입니다. 실제로 일정에 쓰이는 정보가 필요한 단계에서 입력되도록 바꿨습니다.

초기 구상과 변경 이유는 설계 과정에 대한 설명이며, 화면은 실제 구현된 현재 버전입니다.

화면 구성과 구현

일정, 동선, 경비를 함께 판단할 수 있도록

여행 일정을 고칠 때는 장소 이름만으로 결정하기 어렵습니다. 날짜별 시간표와 지도, 예상 경비를 같은 화면에 배치하고, 방문 순서 변경과 장소 교체를 화면에서 바로 할 수 있게 했습니다.

설계의 확장 범위

제주는 시연 사례, 구조는 국내 여행을 기준으로

국내의 다양한 출발지·목적지와 항공·KTX·자차를 고려했습니다. 지역별 장소·교통·숙소·경로 데이터가 확보되면 다른 국내 지역에도 같은 일정 생성·수정 흐름을 적용하도록 설계했습니다.

화면별 설계 이유와 실제 화면

예산과 여행 날짜를 정한 뒤, 교통편과 숙소를 고릅니다.
여기에 여행 테마와 음식 취향을 더해 나에게 맞는 일정을 만듭니다.

예산 → 출발지·목적지 → 날짜 → 교통·숙소 → 취향 → 일정 생성

01 · 예산

예산을 가장 먼저 정합니다

‘주어진 예산 안에서 일정을 만든다’는 목표를 첫 화면에 반영했습니다.

사용자가 정한 예산을 바탕으로 교통편과 숙소를 고르고, AI가 여행 일정을 만들도록 했습니다.

02 · 출발지와 목적지

출발지는 정확한 위치로, 목적지는 가고 싶은 장소로

출발지: 시·구·동과 주소

자차 여행은 어디서 출발하느냐에 따라 이동 시간이 달라집니다.
시·구·동 단위 지도와 주소 입력으로 출발 위치를 자세히 정할 수 있게 했습니다.

목적지: 관광 지역과 명소

여행을 생각할 때는 ‘어느 구’보다 ‘속초에 갈까, 해운대에 갈까’를 먼저 떠올립니다.
그래서 목적지는 관광 지역과 명소를 중심으로 고르게 했습니다.

03 · 날짜와 숙소

날짜를 정한 뒤, 교통과 숙소를 고릅니다

교통편과 숙소를 선택하려면 여행 날짜가 먼저 필요합니다.

교통편과 객실 상황은 날짜에 따라 달라지므로, 날짜를 먼저 고르게 했습니다.
숙소를 선택하면 그 위치를 중심으로 관광지와 식당을 추천합니다.

04 · 결과 확인과 편집

만든 일정은 직접 바꿀 수 있습니다

선택한 항공편 시간과 숙소 위치에 맞춰 날짜별 일정을 보여줍니다.
시간표 옆에 지도를 두고, 방문 순서를 바꾸거나 다른 장소로 교체할 수 있게 했습니다.

다음에 확인할 사용자 경험

입력 순서와 조건별 시간 설정은 설계 판단입니다. 이 포트폴리오에는 사용자 테스트로 입증한 편의성 향상이나 이탈률 개선 수치를 제시하지 않았습니다.

  • ‘예산 안에서 2박 3일 여행 만들기’ 과제로 입력 단계의 혼란과 되돌아가는 지점 관찰
  • ‘여행 중 식당 한 곳 바꾸기’ 과제로 모바일 버튼 발견과 변경된 동선 이해 확인
  • 관찰 결과를 바탕으로 화면을 수정하고, 변경 전후의 같은 과제 수행 비교

위 항목은 향후 검증 계획이며, 완료된 사용자 조사나 성과가 아닙니다.

시연 범위와 운영 안내

항공·숙소 금액은 예상 견적이며, 렌터카 업체·가격은 시연용 데이터입니다. 일부 상세 정보는 요청 실패 시 대체 데이터를 사용합니다. 실제 결제·예약 확정 기능이나 국내 모든 지역의 품질 검증을 의미하지 않습니다.

실습용 AWS 환경은 2026년 10월 8일 종료 예정입니다. 이후 온라인 AI 생성·외부 데이터 조회는 이용할 수 없지만, 이 페이지의 영상과 발표자료는 계속 확인할 수 있습니다. PWA의 정적 자산 캐시와 온라인 AI·지도 기능은 구분됩니다.
