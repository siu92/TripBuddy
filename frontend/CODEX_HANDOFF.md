# TripBuddy 프로젝트 인수인계

## 프로젝트 기본 정보

- 프로젝트: `TripBuddy` — AI 기반 국내·해외 여행 계획 및 예산 비교 플랫폼
- 기술: Vite + React 프론트엔드
- 로컬 폴더: `C:\frontend\frontend`
- 개발 주소: `http://127.0.0.1:5175/`
- 검증 명령: `npm run build`
- 큰 변경 뒤에는 `Backup 파일` 폴더에 ZIP 백업을 만든다.
- URL이 바뀌면 반드시 사용자에게 알린다. 현재 URL은 변경되지 않았다.

## 작업 원칙

- 사용자가 따로 요청하지 않은 기존 기능·문구·구성은 제거하거나 임의 변경하지 않는다.
- 화면을 바꾼 뒤에는 빌드 확인을 한다.
- 사용자가 말한 금액, 항공편, 숙소 등은 발표용 시연 데이터이며 실제 예약 서비스와 혼동되지 않도록 필요한 안내 문구를 유지한다.
- 비용은 기본적으로 **1인 기준**으로 보여 준다. 공통 비용은 인원수로 N/1 분배한다.
- 큰 기능 묶음이 끝나면 ZIP 백업을 생성한다.

## 2026-09-10 고객사 제출 전 최종 검수 메모

### 이번 작업에서 확정한 구조

- 메인 화면의 `투어 & 액티비티`와 `타임세일 숙소`는 하나의 4초 타이머와 일시정지 상태를 공유한다. 두 줄은 같은 React 렌더링 주기에서 동시에 한 칸 이동하며, 어느 한쪽에 마우스를 올리거나 터치하면 둘 다 멈춘다.
- 항공·숙박·렌터카·관광지·식당·경비·경로 응답은 화면 컴포넌트에서 직접 해석하지 않고 `src/api/normalizers.js`의 공통 DTO로 변환한다.
- 일정 장소 변경과 드래그 순서 변경은 `/api/v1/trips/plans/{planId}/recalculate`에 순차 전송한다. 요청 큐와 revision 비교를 사용하므로 늦게 도착한 과거 응답이 최신 화면을 덮어쓰지 않는다.
- TMAP/Kakao Mobility의 거리·시간 단위는 각각 `m → km`, `sec → min`으로 정규화한다. Kakao Local의 `x/y` 문자열 좌표는 `longitude/latitude` 숫자로 바꾼다.
- 오피넷 평균 유가는 `B027=휘발유`, `D047=경유`, `K015=LPG`로 매핑하며 `/api/v1/fuel-prices/average` 어댑터를 사용한다.
- 저장된 여행 초안의 출발일이 오늘보다 이전이거나 날짜 범위가 역전되면 오늘 날짜부터 다시 선택하게 하고, 해당 날짜에 종속된 교통수단 선택을 초기화한다.
- 달력의 최대 예약일은 고정 날짜가 아니라 접속일 기준 1년 뒤까지 자동으로 이동한다.
- 외부 커머스 이미지가 실패하면 빈 카드 대신 브랜드 톤의 대체 상태를 보여 준다. 찜 버튼은 실제 선택/해제 상태와 접근성 속성을 함께 갱신한다.
- React 19와 peer dependency가 충돌하던 `react-simple-maps`를 `5.0.3`으로 올렸다.
- 여행 테마에서 쇼핑을 제거했고 테마와 음식 선호는 각각 최대 3개로 제한한다. 저장 데이터도 허용된 코드만 중복 없이 3개까지 정규화한다.
- 음식 선호의 기본 설정 카드에는 이름 아래 36px 높이의 대표 이미지를 표시한다.
- 날짜 UI와 안내 문구는 국내외 공통으로 `출발일 / 도착일` 용어를 사용한다.
- 데스크톱 헤더는 `회원가입 / 로그인 / 내 예약 / 여행 만들기` 순서다. 좁은 모바일 헤더에서는 회원가입과 내 예약을 숨겨 핵심 로그인·여행 만들기 동작의 터치 폭을 확보한다.

### 백엔드 연결 시 지켜야 할 계약

- 자세한 필드와 예시는 `BACKEND_INTEGRATION_GUIDE.md`를 기준으로 한다.
- 장소 ID는 화면 순서가 바뀌어도 유지되는 영구 ID여야 한다. 프론트의 배열 인덱스를 서버 ID로 사용하면 안 된다.
- 금액은 숫자 KRW, 좌표는 WGS84, 거리 `km`, 이동시간 `minutes`, API 시간 원본은 ISO 8601을 기본 계약으로 유지한다.
- 항공·숙소·렌터카 제휴 링크는 서버가 반환한 HTTPS URL만 사용하고, 없을 때는 예약 가능 상태로 표시하지 않는다.
- 지도 제공자 키와 외부 API 키는 브라우저 번들에 넣지 않는다. 백엔드 프록시에서 호출하고 허용 도메인·쿼터·타임아웃을 관리한다.
- TMAP/Kakao/식당·숙박/오피넷 중 일부가 실패해도 전체 일정 생성을 실패시키지 말고, 마지막 정상 경로 또는 추정값을 `source`와 `estimated` 표시와 함께 반환한다.

### 최종 검증 결과와 남은 운영 과제

- `node --test tests/travelSchedule.test.cjs tests/apiNormalizers.test.mjs`: 20개 통과.
- `npm run build`: 성공. PWA 서비스 워커와 정적 산출물 생성 확인.
- `npm ls react react-dom react-simple-maps`: React 19 peer dependency 충돌 없음.
- 패키지 설치 결과 알려진 취약점 0건.
- 실제 TMAP/Kakao 경로, 네이버 장소 가격, 제휴 예약 재고는 현재 시연용 mock과 서버 폴백을 함께 사용한다. 고객사 운영 키와 계약 API가 준비되면 `VITE_API_BASE_URL`을 연결하고 mock 모드를 끈 뒤 동일 시나리오로 통합 테스트한다.
- 프로덕션 번들 JS가 약 692KB로 Vite 500KB 권고를 넘는다. 기능에는 영향이 없지만, 출시 전 `PlanFullscreen`·지도·비교 모달을 동적 import로 분리하면 첫 화면 로딩을 줄일 수 있다.

## 브랜드·메인 화면

- 브랜드명: `TripBuddy`
- 핵심 문구: `내 예산에 딱 맞춘 단 하나의 길, TripBuddy.`
- 현재 히어로 배경은 산토리니 → 하와이 → 우유니 반영 호수 → 에메랄드빛 알프스 호수 순서의 4장 자동 전환 슬라이드다. 외부 이미지 링크를 제거하고, 우유니 장면도 프로젝트 내부 고해상도 이미지로 교체해 네트워크 상태와 관계없이 선명하게 표시한다.
- 이전 알프스 사진과 도시 야경은 사용자 요청으로 제외했으며, 최신 알프스 호수 사진은 사용자가 새로 첨부해 추가한 이미지다.
- 프로젝트 내부에는 과거 히어로 미리보기 HTML 파일도 남아 있다.

## 주요 사용자 시연 시나리오

### 1. 한림 숙소 기준 일정

1. 제주도 / 2박 3일 / 총 3명 / 1인 예산 입력
2. 출발지 서울 여부 확인 → `예`
3. 항공 이동 여부 확인 → `예`
4. 가는 편과 오는 편을 각각 선택
5. 제주 현지 이동수단으로 렌터카 선택
6. 한림리조트 선택
7. AI 로딩 후 한림·협재·애월 중심의 전체 일정 확인

### 2. 숙소를 히든 클리프로 변경

1. 전체 일정 화면에서 `AI에게 숙소 다시 추천받기` 클릭
2. `히든 클리프 호텔&네이쳐` 선택
3. 일정은 중문·서귀포 권역(중문색달해수욕장, 천제연폭포, 주상절리대 등) 중심으로 재설계
4. 화면에서 `− 한림리조트`와 `＋ 히든 클리프 호텔&네이쳐` 변경 내역이 보여야 한다.

### 3. 일정 장소 변경

- 전체 일정의 각 장소 블록 또는 `장소 변경` 버튼을 클릭한다.
- 추천 장소 또는 직접 입력한 장소로 교체한다.
- 교체 후 이동 동선, 일정, 1인 예상 경비를 다시 계산하는 시연 흐름이다.

## 현재 구현 완료 상태

### 메인 여행 설계 화면

- 프롬프트 입력창에 전송 버튼과 Enter 전송을 구현했다. Shift + Enter는 줄바꿈이다.
- 기본 프롬프트 예시는 회색 placeholder로 표시된다.
- 여행지 선택은 국내/해외 탭, 대표 지역 사진, 직접 입력을 지원한다.
- 날짜는 출발일과 도착일만 먼저 고른다.
- 제주도와 도착일을 선택하면 AI 질문이 자동으로 열린다.
- 질문 흐름:
  - `출발지가 서울인가요?` → 예/아니오
  - 예 선택 시 `교통수단은 항공인가요?` → 예/아니오
  - 항공 예 선택 시 가는 편 선택 → 오는 편 선택 → 제주 현지 이동수단 선택
  - 항공 아니오 선택 시에만 직접 시간 설정 UI가 노출된다.
- 항공편은 가는 편/오는 편을 분리한 2단계 선택이며, 김포·인천 탭과 시간순/최저가순 정렬을 지원한다.
- 가는 편을 고르면 항공 목록을 바로 교체하지 않고, `가는 편을 선택했어요. 이제 돌아오는 편을 선택하겠습니다.`라는 AI 전환 안내를 거친 뒤 오는 편 비교 창을 연다.
- 기본 `시간순`은 특가 노출 순서가 아니라 실제 출발 시각이 빠른 순서다. 발표 기준 항공편은 인천 출발 대한항공 `10:00 → 11:15`, 제주 출발 대한항공 `18:15 → 19:25` 왕복 특가다. 이 두 편을 고르면 전체 일정의 첫날 도착·마지막 날 공항 이동 시간도 그 시간에 맞춰 다시 계산된다.
- 항공 특가는 `오늘만` 배너, 정가 취소선, 할인율, 잔여석으로 강조한다.
- 총인원은 +/− 대신 오른쪽 하단의 직접 입력 방식이다.
- 숙소 비교는 큰 팝업, 가격대·권역·검색·리뷰순/최저가순 정렬을 제공한다.
- 호텔 카드에는 평점, 추천 리뷰 수, 특가/잔여 객실 정보를 보여 준다.
- 렌터카 비교는 큰 팝업, 차량 이미지, 2박 3일 총 대여료, 보험·인수·반납·취소 정보와 특가를 제공한다.
- 렌터카를 확정하면 `여행 속도`와 `여행 테마`를 묻는 별도 AI 팝업이 열리며, 완료한 선택은 메인 화면과 AI 체크 영역에 즉시 반영된다.
- 테마 선택 완료 뒤에는 `이제 숙소를 선택하겠습니다.` AI 안내를 거쳐 큰 숙소 비교 창을 열며, 숙소 선택 뒤에는 1인 예산 충족 여부와 `이제 일정을 생성하러 가볼까요?` 안내가 차례로 표시된다. 마지막 안내의 버튼은 메인 화면의 일정 생성 버튼으로 부드럽게 이동·포커스한다.
- 총인원은 입력하는 즉시 계산에 반영된다. 숙소 선택 단계와 일정 생성 뒤의 인원 N/1 값이 서로 달라지지 않도록 수정했다.
- AI 단계 안내 팝업에는 숙소·예산·일정 생성 의미가 바로 보이는 큰 호텔·코인·일정표 아이콘을 사용한다.
- 한림/중문 일정의 식비·체험·공통비 상세 항목은 전체 1인 예산과 합계가 맞도록 구성했다. 기본 발표 조합(인천 대한항공 특가 + 빌리카 + 한림리조트, 3명)은 1인 약 508,600원으로 60만 원 예산 안에 표시된다.
- `내 예산으로 여행 만들기` 클릭 시 전체 화면 AI 로딩(약 3초) 후 일정 화면으로 부드럽게 이동한다.

### 전체 일정 화면

- 날짜별 타임라인과 3일을 한눈에 보는 시간표 탭이 있다.
- 일정 카드마다 장소 변경이 가능하다.
- 지도는 실제 일정 장소 기반의 다중 경유지 Google Maps embed 경로를 사용한다.
- 숙소 변경 AI 질문과 숙소 팝업을 전체 일정에서 바로 열 수 있다.
- 일정/시간표 탭은 작게 두고, `혹시 숙소를 변경하고 싶으신가요?` 영역은 가로로 넓고 눈에 잘 띄는 안내 카드로 표시한다.
- 전체 일정에서 숙소를 바꾸면 즉시 덮어쓰지 않는다. `변경된 숙소를 기반으로 일정을 새롭게 생성하겠습니다.` AI 로딩을 약 3초 보여 준 뒤 전체 일정 화면을 다시 열고, 화면은 위에서 아래로 새로 만들어지는 애니메이션을 적용한다.
- `한림리조트 → 히든 클리프 호텔&네이쳐` 변경 시에는 기존 한림·협재 중심 일정 대신 중문·서귀포 중심의 일정으로 새로 만든다. 첫날은 인천 대한항공 도착(11:15) → 렌터카 → 중문 점심 → 히든 클리프 체크인 → 천제연폭포 → 중문색달해수욕장 → 중문 저녁 순서다. 마지막 날은 제주 출발 18:15 대한항공 탑승을 위해 16:45 공항 도착 기준으로 구성된다.
- 일정 항목은 연한 테두리의 클릭 가능한 블록이며, `장소 변경` 버튼은 오른쪽의 크게 보이는 독립 동작으로 배치한다. 장소 변경 팝업도 넓은 화면에서는 오른쪽에 크게 표시한다.
- 항공·숙소·음식점·체험 카드에는 예상 비용을 표시한다.
- 식비/카페/체험처럼 변동 가능한 비용은 `약 1인`으로 표시하고 오차 안내 문구를 둔다.
- 상세 경비는 접기/펼치기 방식이며, 개인 비용과 공통 비용 N/1을 나누어 보여 준다.
