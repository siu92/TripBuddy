03

추후 백엔드에서 연결할 항목

전면 개편이 아니라 필요한 데이터와 조회 기능을 단계적으로 추가하면 됩니다.

연동 1

관광지 상세 데이터

우선순위 높음

지역형 관광지를 포함해 일정에 들어가는 모든 장소에 안정적인 고유 ID와 상세 정보를 제공합니다.

idnamecategoryNameintroductionrepresentativeImageUrladdresslatitudelongitudephoneNumbertags
연동 2

대체 장소 검색 API

DB 활용 핵심

현재 장소와 좌표, 유형, 선호 테마, 제외 목록을 받아 DB에서 적합한 후보를 반환합니다. 프론트가 거리·취향 점수를 표시할 수 있습니다.

currentPlaceIdlatitudelongitudeplaceTypepreferenceTagsexcludePlaceIdsradiusKmlimit
연동 3

일정 순서 변경 저장

모든 일정 항목에 고유 eventId를 제공하고, 정렬된 ID 목록과 고정 일정 여부를 받아 서버에서도 변경 결과를 영구 저장합니다.

revisionIddayIndexeventIdsisLockedstartAtendAttravelMinutes
연동 4

식당 예상 비용

무료와 가격 미확인을 구분하기 위해 미확인 가격은 0 대신 null을 권장합니다. 대표 메뉴와 출처를 함께 주면 프론트 추정치를 제거할 수 있습니다.

pricePerPersonrepresentativeMenumenuPricepriceSourceapproximatepriceUpdatedAt
연동 5

이미지·후기 연결

사용 권한이 확인된 대표 이미지와 공식 지도 또는 카카오플레이스 URL을 반환하면 상세 화면에서 그대로 연결합니다.

representativeImageUrlimageUrlsplaceUrlratingreviewCountreviewSummary
중요: 기존 백엔드 로직을 변경할 필요는 없습니다.

현재 API 응답에 필요한 필드를 보완하거나 별도의 조회 API를 추가하는 방식으로 단계적 연결이 가능합니다. 프론트 폴백은 실제 데이터가 제공되면 자동으로 후순위가 됩니다.
