# 핵심 훅 책임 분리 · 2026-11-01

## 판단과 변경

4,280행의 핵심 훅에는 서로 다른 변경 이유를 가진 경비 계산과 두 후보 조회가 남아 있었습니다. 입력값 변경에 따른 후속 선택 초기화·생성·편집은 연결성이 높아 그대로 두고, 다음 책임만 분리했습니다. 핵심 훅은 3,168행으로 줄었으며 파일 줄수는 성능 지표가 아닙니다.

| 책임 | 위치 | 보존한 계약 |
| --- | --- | --- |
| 1인/공동 경비 계산 | [tripCostModel](../frontend/src/planner/tripCostModel.js) | 기존 산식, 예약 이벤트 중복 제외, 서버 견적 보정, 생성 전 안내액 유지 |
| 경비 스냅샷 | [useTripCostEstimate](../frontend/src/hooks/useTripCostEstimate.js) | 여행 ID별 저장 형식 유지 |
| 항공 조회 | [useFlightOptions](../frontend/src/hooks/useFlightOptions.js) | 선택 항공편 유지, 오는 편 사전 조회와 기존 공유 캐시 유지 |
| 숙소 조회 | [useStayOptions](../frontend/src/hooks/useStayOptions.js) | 선택 숙소 유지, 가격 미제공 숙소 허용 |
| 조회 순서 | [useLatestPlannerRequest](../frontend/src/hooks/useLatestPlannerRequest.js) | 새 검색·조건 변경·초기화·언마운트 이후 도착한 이전 응답 무시 |
| 알림 | [usePlannerNotice](../frontend/src/hooks/usePlannerNotice.js) | 새 알림이 이전 타이머로 일찍 지워지지 않게 타이머 교체 |

숙소의 기타 지역 입력란은 `document.createElement`로 주입하던 방식에서 같은 위치·클래스의 React 제어 입력으로 변경했습니다. 화면 모양이나 CSS 규칙은 바꾸지 않았습니다.

조회 순서 제어는 오래된 성공뿐 아니라 실패와 `finally`의 로딩 해제에도 적용합니다. 항공 API에서 공유 중인 요청을 취소하면 다른 소비자에게 영향을 주므로 네트워크 취소 대신 결과 적용을 제한합니다. 모달을 닫는 것만으로 선택한 후보를 지우지는 않습니다.

## 검증

- 프론트 기본 테스트 55개 통과: 기존 48개 + 조회 순서 3개 + 경비 모델 4개.
- 변경 전/후 경비 함수를 동일 입력 96가지(인원·교통·현지 이동·서버 견적 조합)로 비교해 출력 일치. 함수 반환값을 제외한 모든 반환 데이터와 장소 비용 함수의 지정가 처리를 비교했습니다.
- 핵심 훅에 남은 선언 77개와 effect 9개의 구문을 기존 코드와 비교해 일치를 확인했습니다. 기존 공개 반환 필드 185개도 유지했으며 React 제어 입력용 필드 2개만 추가했습니다.
- 실제 Edge 브라우저에서 서로 다른 항공 조회의 응답 역전, 이전 실패/finally, 날짜 변경, 숙소 목적지 변경, 연속 알림, 언마운트 후 응답 처리를 확인했습니다. 기존 항공 캐시가 같은 쿼리를 공유하므로 역전 검사는 서로 다른 공항 쿼리로 구성했습니다.
- PC 앱 로딩·인원 3명 초안 복원·숙소 지역 입력과 모바일 390px 가로 넘침 없음을 확인했습니다. 빌드 CSS는 변경 전과 SHA256이 동일합니다. 브라우저 검사는 이번 로컬 검수이며 기본 CI에 연결된 E2E 검사는 아닙니다.
- AWS·실제 항공 공급자·지도 인증을 포함한 운영 환경 전체 연결은 재실행하지 않았습니다. 백엔드 실행 코드는 변경하지 않았습니다.

## 남긴 책임

핵심 훅의 입력 변경·예약 초기화·일정 생성·저장 복원은 계속 함께 읽습니다. 줄수만 줄이기 위해 setter 다수를 전달하는 여러 훅으로 다시 나누지 않았습니다. 다음 분리에는 생성/편집의 취소·동시 저장과 전체 화면 회귀 검사를 먼저 준비해야 합니다.

설계 근거: React의 [의미 있는 책임 단위의 커스텀 훅](https://react.dev/learn/reusing-logic-with-custom-hooks), [Effect cleanup과 응답 경합 방지](https://react.dev/reference/react/useEffect)를 참고했습니다. 추출 자체를 성능 개선 수치로 표현하지 않습니다.
