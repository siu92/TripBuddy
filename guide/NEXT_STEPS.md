# 다음 개선 과제

아래는 코드와 빌드에서 확인한 후속 과제입니다. 완료된 구현이나 검증 성과와 구분합니다. AWS 재가동은 현재 개선 범위에서 제외합니다.

| 우선순위 | 과제 | 필요한 이유 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 화면 상호작용의 자동 회귀 검사 | 현재 순수 함수·API 계약 테스트와 수동 화면 검사를 넘어, 조건 입력·초안 복원·편집 동작을 반복 확인할 필요가 있습니다. | 브라우저에서 핵심 입력·복원·편집·실패 상태를 재현하고 CI에 연결 |
| 2 | 실제 노출 이미지와 최초 번들 점검 | 일반 빌드 JS 약 845kB(압축 약 264kB), 일부 이미지가 1MB 이상입니다. 실제 로딩 시간 개선량을 아직 측정하지 않았습니다. | 화면별 필요 자산 확인 → 이미지 변환/지연 로딩·코드 분할 → 같은 조건의 전후 측정 |
| 3 | 남아 있는 큰 훅과 응답 변환 분리 | 독립 함수는 분리했지만 훅은 약 4,280행입니다. 상태와 비동기 요청의 책임을 더 좁힐 여지가 있습니다. | effect 순서·입력 초기화·저장 계약을 검사하면서 기능 단위로 분리 |
| 4 | 전역 CSS의 단계적 범위 축소 | 전역 CSS가 6천 행 이상이며 보정 규칙이 누적되어 있습니다. 이름만 기준으로 옮기면 cascade가 달라질 수 있습니다. | 대표 화면 비교를 준비한 뒤 컴포넌트 단위로 이동, PC/모바일 전후 확인 |

먼저 회귀 검사를 보강한 뒤 구조·성능 변경을 진행하는 순서로 잡았습니다. 이번 README 개선에서는 위 기능·의존성·스타일 동작을 변경하지 않았습니다.
